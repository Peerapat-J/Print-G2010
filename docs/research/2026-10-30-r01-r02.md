# R-01 / R-02 — macOS baseline และ USB hardware findings

วันที่ตรวจ: 2026-10-30 (Asia/Bangkok) เครื่องจริงที่เชื่อมต่อ Canon PIXMA G2010

เอกสารนี้เป็น baseline ก่อนติดตั้ง SANE/ทดลอง scan-print อ่าน [ผล R-03/R-04 รอบถัดมา](2026-10-30-r03-r04-hardware.md) สำหรับสถานะ hardware ล่าสุด

## ข้อสรุป

**พบ Canon G2010 ใน USB registry, System Information และ CUPS USB discovery แล้ว** ปัญหาที่ผู้ใช้รายงานว่าไม่เห็นเครื่องหมายถึงการรัน `system_profiler SPUSBDataType` แล้วไม่ได้ output ไม่ใช่รายงานว่าเครื่องหายจาก System Settings หรือหน้าต่างพิมพ์

บนเครื่องนี้ `SPUSBDataType` ให้ output ว่าง แต่รายการชนิดข้อมูลรองรับแสดง `SPUSBHostDataType` และการเรียกชนิดนี้แสดงเครื่องจริง ไม่ควรตีความคำสั่งเดิมที่ว่างเป็นหลักฐานว่า USB เสียหรือไม่สามารถรองรับ G2010 ได้

มีคิว `Canon_G2010_series` อยู่แล้ว ใช้ PPD **Canon G2000 series 16.80.0.0** และชี้ไปยัง USB URI ของ G2010 ที่ค้นพบ แต่ยังไม่ได้ส่งงานพิมพ์ จึงยังไม่ยืนยันความเข้ากันได้ ขณะตรวจยังไม่มี SANE CLI ใน Homebrew/PATH และยังไม่ได้ทดลองสแกน

### Architecture baseline ที่เสนอสำหรับการทดลอง

- Hardware validation รอบแรกจำกัดที่ Apple Silicon arm64 และ macOS 27.0.1 เครื่องนี้ ยังไม่ประกาศ minimum deployment version หรือรองรับ macOS/Intel รุ่นอื่น
- System printing ต้องใช้คิวของ macOS และทำงานเมื่อแอป SwiftUI ไม่ได้เปิดอยู่ ตาม requirement เดิม
- แยก print backend/transport, scanner backend/service และ SwiftUI/AppKit/PDFKit UI; ยังไม่สร้าง abstraction จนกว่าจะมีผล backend จริง
- คง CUPS + ไดรเวอร์เดิมเป็นทางทดลองแรก เพราะมีการติดตั้งและ enumeration จริงแล้ว หากใช้ไม่ได้จึงประเมิน backend ที่นำกลับมาใช้ได้และ local IPP Printer Application
- Local IPP เป็นตัวเลือกสถาปัตยกรรม ยังไม่ได้พิสูจน์บน Mac นี้ และไม่ใช่การเพิ่ม network printing ใน MVP
- Scanner candidate คือ SANE pixma; การมี Canon ICA scanner package เดิมไม่ได้พิสูจน์ว่า G2010 ใช้งานได้
- ยังไม่จำเป็นต้องเลือก kernel extension, DriverKit หรือเขียน USB transport ใหม่จากหลักฐานรอบนี้

R-01: ตรวจเครื่องและบันทึก baseline แล้ว; support matrix, deployment target, distribution/license และ architecture สุดท้ายยังรอ R-03–R-06

## R-02: USB และ CUPS

### หลักฐาน USB ที่ปกปิดข้อมูลระบุตัวเครื่องแล้ว

คำสั่ง:

```sh
system_profiler -listDataTypes | rg -i USB
system_profiler SPUSBHostDataType
```

ข้อมูลสำคัญจาก output:

```text
SPUSBHostDataType

G2010 series:
  Connection Type: Removable
  Manufacturer: Canon
  Serial Number: [REDACTED]
  Link Speed: 480 Mb/s
  USB Vendor ID: 0x04a9
  USB Product ID: 0x183a
  USB Product Version: 0x0111
```

`ioreg -p IOUSB -l -w0` ยืนยัน node `G2010 series`, `idVendor=1193` (`0x04a9`), `idProduct=6202` (`0x183a`), `UsbLinkSpeed=480000000`, `bcdUSB=512` (`0x0200`) และ current configuration 1

`ioreg -r -c IOUSBHostInterface -l -w0` พบ interface ของ VID/PID เดียวกัน:

| Interface | Class | Subclass | Protocol | Endpoints |
| --- | --- | --- | --- | --- |
| 0 | 255 (`0xff`) | 0 | 255 (`0xff`) | 3 |
| 1 | 7 (`0x07`) | 1 | 2 | 2 |

Interface 0 เป็น vendor-specific; ยังไม่ได้พิสูจน์การสแกนผ่าน interface นี้ Interface 1 เป็น USB printer-class bidirectional interface การ enumerate descriptor ไม่ได้พิสูจน์ raster protocol, endpoint transfers, คุณภาพพิมพ์ หรือความเสถียรหลัง reconnect/sleep

### หลักฐาน CUPS และไดรเวอร์เดิม

```text
$ lpinfo -v
direct usb://Canon/G2010%20series?serial=[REDACTED]

$ lpstat -p Canon_G2010_series
printer Canon_G2010_series is idle. enabled since [historical timestamp]

$ lpstat -r
scheduler is running
```

- CUPS พบเครื่องใน USB discovery และมีคิว Canon ที่ idle/enabled; default printer เป็นคิวอื่น ไม่ใช่ Canon นี้
- `lpstat -v Canon_G2010_series` แสดง USB URI ของรุ่น G2010 แต่ข้อสรุปเดิมว่า serial ตรงกับ discovery ไม่ถูกต้อง: รอบแรกไม่ได้ตรวจเทียบค่าเต็มอย่างเพียงพอ [การตรวจเทียบภายหลัง](2026-10-30-print-queue-uri.md) พบ serial ไม่ตรงและได้แก้เฉพาะ URI ของคิวแล้ว
- `/etc/cups/ppd/Canon_G2010_series.ppd` ระบุ `ModelName` / `NickName`: `Canon G2000 series`, `FileVersion`: `16.80.0.0`, `PCFileName`: `CNIJ465.ppd`
- PPD อ้างถึง `Raster2CanonIJS` และ `Command2CanonIJ` ใน `/Library/Printers/Canon/BJPrinter/Filters/`; `file` ยืนยัน executable ทั้งสองมี arm64 และ x86_64 slices จึงไม่พบเหตุให้สรุปว่าสองไฟล์นี้เป็น Intel-only แต่ dependencies และ runtime compatibility ยังไม่ได้ทดสอบ
- `lpoptions -p Canon_G2010_series -l` อ่านตัวเลือกได้ เช่น A4, 300/600 dpi, grayscale และ quality; สิ่งเหล่านี้เป็นตัวเลือกจากไดรเวอร์ G2000 ไม่ใช่ผลยืนยันว่าทุกตัวเลือกทำงานกับ G2010
- มี Canon ICA scanner app ใน `/Library/Image Capture/Devices/Canon IJScanner15f.app`; ยังไม่ได้เปิดหรือทดสอบ

**ข้อจำกัดของเครื่องมือ:** ตอนรันใน sandbox, `sysctl` ถูกปฏิเสธและ `lpinfo`/`lpstat` ให้ `Bad file descriptor` / `scheduler is not running` การตรวจซ้ำด้วยสิทธิ์นอก sandbox แบบอ่านข้อมูลพบ CUPS ทำงานและแสดงคิวจริง จึงไม่ถือผลผิดพลาดชุดแรกเป็น blocker ของระบบพิมพ์ ห้าม reset/restart/install เพื่อแก้ข้อผิดพลาดจาก sandbox โดยไม่มีหลักฐานเพิ่ม

R-02: ยืนยัน enumeration และ CUPS discovery สำเร็จ ณ เวลาตรวจ; ยังไม่มี unplug/replug, port/cable comparison หรือ sleep/wake test ไม่ต้องเปลี่ยนสาย/adapter เพื่อแก้ “ตรวจไม่พบ” จากหลักฐานปัจจุบัน แต่ยังไม่รับรองเสถียรภาพระยะยาว

## หลักฐานจาก upstream ที่ช่วยเลือกงานถัดไป

ตรวจเมื่อ 2026-10-30 แยกจากผล hardware:

- [SANE supported backends](https://www.sane-project.org/sane-backends.html) แสดง G2010 USB `04a9/183a` เป็น Complete สูงสุด 600 DPI และ [sane-pixma manual](https://www.sane-project.org/man/sane-pixma.5.html) ระบุ G2010 ในรายการรุ่น แหล่งนี้สนับสนุนการเลือก candidate แต่ไม่ใช่ผลสแกนบน Mac นี้ หมายเหตุ: search index อ่านข้อมูลได้ แต่เปิดหน้าตรงผ่านเครื่องมือเว็บครั้งนี้ได้รับ 502 จึงต้องยืนยันอีกครั้งกับ backend version ที่ติดตั้งจริง
- [Homebrew sane-backends](https://formulae.brew.sh/formula/sane-backends) แสดง version 1.4.0, Apple Silicon bottle สำหรับ macOS 27 และ dependency libusb; เป็นเส้นทางทดลองที่เป็นรูปธรรม ยังไม่ได้ติดตั้ง
- [Canon G2000 CUPS 16.91.0.0](https://asia.canon/en/support/0101155713) ระบุรองรับ G2000 และ macOS 27 โดยไม่ได้ระบุ G2010 จึงไม่ใช่หลักฐานว่าใช้กับ G2010 ได้ ไดรเวอร์ที่ติดตั้งจริงเป็น 16.80.0.0; ยังไม่ได้ update
- [Gutenprint upstream](https://gimp-print.sourceforge.io/) ประกาศเลิกผลิต binary สำหรับ macOS ตั้งแต่ 2024-07-07 จึงต้องประเมินภาระ build/port/distribution ก่อนเลือก ยังไม่ได้ยืนยันว่า G2010 รองรับ
- [OpenPrinting architecture](https://openprinting.github.io/cups/drivers.html) อธิบายแนวทาง Printer Applications สำหรับ legacy drivers; เป็นตัวเลือกวิจัย ไม่ใช่หลักฐานว่า G2010 หรือ macOS integration ผ่านแล้ว

### Reuse / adapt / implement decision ณ ตอนนี้

| ส่วน | ข้อเสนอ | สิ่งที่ยังต้องพิสูจน์ |
| --- | --- | --- |
| macOS queue / USB printing discovery | Reuse ระบบเดิม | พิมพ์จาก Preview และแอปอื่นได้จริง |
| G2000 print filter | ทดลองของที่ติดตั้งอยู่ก่อน | G2010 compatibility, runtime, output quality; ห้ามสรุปว่าใช้ได้จากชื่อคิว |
| SANE pixma scanner | Reuse candidate ผ่าน R-03 | macOS USB access, real scan, supported options, reconnect |
| Open-source print backend | Research ตาม R-04/R-05 | รุ่น/VID/PID, protocol, build บน arm64, license |
| Scanner adapter / UI | Implement หลัง backend ผ่าน | API, cancellation/recovery, packaging และ license |
| Native raster encoder / custom USB protocol | Deferred | เปิด conditional R&D ต่อเมื่อไม่มี backend ที่เหมาะสม |

ยังไม่ได้คัดลอก third-party code หรือ license มาใน repository นี้ Canon binary เป็นของติดตั้งในเครื่อง ไม่ใช่ส่วนที่พร้อมแจกซ้ำในโครงการ open source ต้องตรวจสิทธิ์ใช้งาน/แจกจ่ายและ license ของ backend ที่เลือกใน R-05 ก่อน integration/distribution

## Blockers และขั้นตัดสินใจ

1. **ยังไม่มี real print result:** คิวมีอยู่และชี้ถูกอุปกรณ์ แต่ต้องมีผู้ใช้อยู่หน้าเครื่อง เตรียมกระดาษ และดู output จริงเพื่อสรุป R-04 ไม่มีหลักฐานว่าจำเป็นต้องเขียน driver ใหม่
2. **ยังไม่มี SANE runtime หรือ real scan result:** เป็น prerequisite ของ R-03 ต้องติดตั้งแล้วทดสอบกับเอกสารที่ผู้ใช้เตรียม; ไม่ถือว่า scanner ใช้ไม่ได้เพียงเพราะ CLI ยังไม่มี
3. **UI visibility ยังไม่ตรวจ:** ผู้ใช้ยืนยันว่ารายงานเดิมมาจากคำสั่ง USB ที่ว่าง จึงยังไม่มีหลักฐานของปัญหาใน Printers & Scanners หรือ Command+P
4. **ยังไม่มี license/distribution decision หรือ support matrix:** ยังเลือก backend สุดท้าย/ประกาศรองรับรุ่น OS เพิ่มไม่ได้

แนะนำงานถัดไปเป็น **R-03: ทดสอบ SANE กับ G2010 จริง** ตามลำดับใน handoff และ **R-04 แบบจำกัด: ทดลองคิว G2000 ที่มีอยู่ก่อนติดตั้งอะไรเพิ่ม** ดู [ร่าง acceptance criteria](next-hardware-task.md) ไม่ควรเปิด P-01 หรือ RD-01 ในตอนนี้
