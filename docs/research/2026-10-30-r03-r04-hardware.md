# R-03 / R-04 — ผลทดสอบฮาร์ดแวร์จริง

วันที่: 2026-10-30 (Asia/Bangkok) ต่อจาก [baseline R-01/R-02](2026-10-30-r01-r02.md)

ผลในเอกสารนี้เป็นการทดลองก่อนแก้ปลายทางคิว ต่อมาพบ serial ของคิวไม่ตรงกับเครื่องจริงและแก้ URI แล้ว อ่าน [printing follow-up](2026-10-30-print-queue-uri.md) ก่อนนำ failure รอบนี้ไปประเมิน driver compatibility

ผู้ใช้กลับมาต่อ USB และยืนยันว่าพร้อมทั้งเอกสารบนกระจกสแกนและกระดาษ A4 สำหรับพิมพ์หนึ่งหน้า รอบนี้ทดสอบด้วยซอฟต์แวร์ที่มีอยู่และ SANE โดยไม่มี implementation ของไดรเวอร์/แอปใหม่ ไม่มีการสร้าง GitHub Issue หรือ commit/push

## ผลสรุป

| เส้นทาง | ผลจริง |
| --- | --- |
| USB enumeration | พบ Canon G2010 `04a9:183a`, 480 Mb/s อีกครั้ง |
| Canon ICA / Image Capture เดิม | ไม่มี scanner ให้เลือกใน Image Capture; ยังสแกนไม่สำเร็จผ่านเส้นทางนี้ |
| SANE pixma discovery | พบ `CANON Canon PIXMA G2010 Series` |
| SANE flatbed color 300 DPI A4 | สแกนสำเร็จ ได้ PNG ที่เปิดได้; ผู้ใช้ยืนยันภาพตรงกับต้นฉบับและครบหน้า |
| สแกนหลังถอดเสียบใหม่ | ค้นพบใหม่และสแกน Color/A4/300 DPI ซ้ำสำเร็จ; ตรวจ PNG และภาพแล้ว |
| G2000 16.80.0.0 + คิว Canon เดิม | งาน 2297 และ retry 2298 หลัง reconnect ติด offline, 0 sheets completed; ผู้ใช้ยืนยันงานแรกไม่มีหน้ากระดาษออก ทั้งสองงานยกเลิกแล้ว |
| Preview / Command+P | ยังไม่ผ่านการทดสอบ; UI automation เปิดไฟล์ไม่สำเร็จ งานทดสอบจริงส่งผ่าน CUPS `lp` |

## Canon scanner เดิม: สิ่งที่ทดสอบ

- เปิด Image Capture: รายการ DEVICES/SHARED ไม่มี scanner
- เปิด Canon IJ Scan Utility2: Product Name มีเพียง Canon G2000 series
- ตรวจ `Canon IJScanner15f.app` version 5.0.0 และ `DeviceMatchingInfo.plist`: USB matching ของ G2000 คือ `04a9:1795`; ไม่พบ G2010 `04a9:183a` ในตารางของ package นี้
- กด Driver ใน utility: ปุ่มถูก disable และไม่มีหน้าสแกนแสดงขึ้น ระหว่างตรวจประมาณหลายนาทีไม่ตอบสนองต่อการปิดแอปตามปกติ จึงส่ง TERM เฉพาะ utility ที่เปิดเพื่อทดสอบก่อนใช้ SANE
- ไม่แก้ plist เพิ่ม VID/PID และไม่ดัดแปลง Canon software ข้อมูล matching เป็นหลักฐานของ package ที่ติดตั้งนี้เท่านั้น ไม่ใช่ข้อสรุปว่า ICA ทุก version ใช้ไม่ได้

## SANE: การติดตั้งและผลจริง

ติดตั้งจาก Homebrew โดยปิด auto-update/cleanup สำหรับคำสั่งนี้:

```sh
HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 brew install sane-backends
```

| รายการ | Version/architecture |
| --- | --- |
| sane-backends | 1.4.0_2; CLI/backend รายงาน 1.4.0 |
| scanimage | Mach-O arm64 |
| libusb | 1.0.30 |
| net-snmp | 5.9.5.2_2 |

Homebrew ติดตั้งสาม formula ข้างต้น ไม่ได้เริ่ม `saned` service ไม่เปลี่ยนคิวพิมพ์หรือ default printer และไม่แก้ config ระบบสแกนเดิม

```text
$ sane-find-scanner -q
found possible USB scanner (vendor=0x04a9 [Canon], product=0x183a [G2010 series]) at libusb:000:001

$ scanimage -L
device `pixma:04A9183A_[REDACTED]' is a CANON Canon PIXMA G2010 Series multi-function peripheral
```

อ่าน `--all-options` จาก device ที่พบจริง: source `Flatbed`, modes `Color/Gray/Lineart`, resolutions `75/150/300/600` DPI ขนาดสูงสุดประมาณ 216.069 × 297.011 mm เป็น capabilities ที่รายงาน ยังไม่ใช่ผล QA ทุกโหมด/ทุกความละเอียด

ตัวเลือกที่ใช้จริง:

```sh
scanimage -d '<discovered-G2010-device-id>' --source Flatbed --mode Color --resolution 300 -x 210 -y 297 --format=png --output-file='<private-local-output.png>' --verbose
```

ผลสแกนแรก:

- Exit code 0; เวลาประมาณ 20.68 วินาที
- PNG RGB, 2480 × 3508 pixels, metadata ประมาณ 300 DPI
- ขนาดไฟล์ 14,097,992 bytes; ตรวจ PNG เปิดได้และเห็นภาพเต็มหน้า
- ผู้ใช้ยืนยันว่า “ภาพตรงกับเอกสารและครบหน้า”
- ไฟล์ภาพอยู่ `/private/tmp/canon-g2010-validation-20261030/` นอก repository ไม่เก็บเนื้อหาเอกสารหรือภาพสแกนใน public findings

### Reconnect

ผู้ใช้ยืนยันถอด USB แล้วเสียบกลับ โดยไม่มีงานสแกนทำงานและยืนยันยกเลิก print job แล้ว เริ่ม discovery ใหม่และสแกน Color/A4/300 DPI ซ้ำหนึ่งหน้า:

- Rediscovery สำเร็จและ scan exit code 0, เวลาประมาณ 18.59 วินาที
- PNG RGB 2480 × 3508 pixels, metadata ประมาณ 300 DPI, 14,114,712 bytes
- ตรวจไฟล์เปิดได้และตรวจภาพว่าเอกสารยังครบหน้า; ผู้ใช้ยืนยันภาพแรก ส่วนภาพหลัง reconnect ตรวจโดย agent
- เป็นหลักฐาน reconnect หนึ่งรอบ ไม่ใช่ stress test หรือ sleep/wake validation

## Printing: ผลที่ผ่านและไม่ผ่าน

เตรียม PDF ทดสอบ A4 หนึ่งหน้าที่ไม่มีข้อมูลส่วนตัว ประกอบด้วยข้อความและช่องสีดำ/แดง/เขียว/น้ำเงิน สร้างด้วย ReportLab และตรวจ rendering ก่อนส่ง

การควบคุมหน้าต่างเปิดไฟล์ใน Preview ผ่าน UI automation ไม่สำเร็จ จึงยังไม่อ้างว่าผ่าน Command+P จาก Preview ทดสอบเส้นทางคิวจริงด้วย:

```sh
lp -d Canon_G2010_series -n 1 -o media=A4 -t 'G2010 hardware validation - one page' '<test-page.pdf>'
```

ก่อนส่งตรวจว่าคิวไม่มีงานค้าง คำสั่งรับงานสำเร็จเป็น `Canon_G2010_series-2297` คิวใช้ Canon G2000 series 16.80.0.0 ตาม baseline เดิม ไม่มีการ update/ติดตั้ง driver เพิ่ม

อ่านผ่าน CUPS Get-Job-Attributes / Get-Printer-Attributes:

```text
job-state = processing
job-state-reasons = job-printing
job-media-sheets-completed = 0
job-printer-state-message = The printer is offline.
job-printer-state-reasons = offline-report,connecting-to-device
printer-make-and-model = Canon G2000 series
```

ผู้ใช้ยืนยันว่าไม่มีอะไรพิมพ์ออกมา จึงยกเลิกเฉพาะงาน 2297 และตรวจยืนยัน `job-state=canceled`, `job-state-reasons=job-canceled-by-user`, `job-media-sheets-completed=0` ไม่ส่งงานซ้ำระหว่างมีงานค้างและไม่ reset printing system

### การทดลองครั้งที่สองหลัง reconnect

หลังผู้ใช้ reconnect USB และ SANE สแกนซ้ำสำเร็จ ทดลอง PDF เดิมหนึ่งหน้า A4 ผ่านคิวและ driver version เดิมอีกครั้งเป็นงาน 2298 โดยเปลี่ยนปัจจัยเฉพาะการ reconnect ทางกายภาพ ไม่ส่งงานพิมพ์ขณะกำลังสแกน

- จำกัดการรอ 60 วินาที อ่าน job attributes เป็นระยะ
- ยังได้ `processing`, `offline-report,connecting-to-device` และ 0 sheets completed
- จึงยกเลิกเฉพาะงาน 2298 ด้วย exit code 0; Get-Job-Attributes ยืนยัน `job-state=canceled`, 0 sheets completed (ขณะกำลังหยุด reason เป็น `processing-to-stop-point`)
- สองครั้งนี้ยังไม่มีหลักฐานว่าพิมพ์สำเร็จ การถอดเสียบหนึ่งรอบไม่แก้ failure ในการทดลองนี้ ยังไม่ได้เปลี่ยน driver version, queue mapping หรือ protocol

ยังไม่ทราบ root cause ของ offline สถานะจาก CUPS ไม่ใช่หลักฐานว่าเครื่องปิดหรือสายเสีย เพราะ SANE สแกนผ่าน USB ได้จริง ไม่ควรสรุปว่า driver G2000 ทุก version ใช้ไม่ได้ หรือสั่ง upgrade เพื่อกลบผล baseline นี้

## ข้อจำกัดเครื่องมือและงานถัดไป

- การอ่าน SANE options นอก sandbox ครั้งหนึ่งถูกระบบตรวจอนุมัติอัตโนมัติปฏิเสธเพราะตรวจไม่เสร็จก่อน deadline; retry ที่ระบบอนุญาตสำเร็จ ไม่ใช่ error ของ scanner
- PDF renderer ครั้งแรกมี fontconfig/cache warnings แต่สร้างภาพได้และตรวจข้อความ/สี/ขอบครบแล้ว ไม่ใช้ warning นี้วิเคราะห์เครื่องพิมพ์
- ไม่พบ `/var/log/cups/error_log` ในการอ่านครั้งนี้ ยังไม่ได้เปิด debug logging หรือแก้การตั้งค่าเพื่อเก็บ log
- ยังไม่ทดสอบ scanner Gray/Lineart/75/150/600 DPI, cancel กลาง scan, sleep/wake หรือ clean installation จึงไม่ประกาศว่าผ่าน scanner MVP ทั้งหมด

**ข้อเสนอ:** SANE pixma เป็น candidate สำหรับ S-01 ที่มีหลักฐาน hardware รองรับแล้ว ตรวจ R-05 เรื่อง license/distribution ก่อนเริ่ม adapter แบบ discover + single-page scan ส่วน R-04 ให้แยกงานวิเคราะห์ CUPS offline ของ version เดิม (queue/device mapping, backend/filter runtime, สถานะเครื่อง) แล้วเลือกการทดลองที่เปลี่ยนทีละปัจจัย ไม่มีเหตุให้เริ่ม native raster encoder จากผล offline สองครั้งนี้
